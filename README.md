# RAG Bot — Chat with PDFs

A small Retrieval-Augmented Generation (RAG) service built with Node.js, Express, and MongoDB Atlas Vector Search. Upload a PDF, it gets chunked and embedded, and you can then ask natural-language questions that are answered strictly from the content of the documents you've ingested — with cited sources.

## Features

- **PDF ingestion** — upload a PDF, extract its text, split it into overlapping chunks, embed each chunk, and store the vectors in MongoDB.
- **Semantic Q&A** — ask a question and get an answer generated by Gemini, grounded only in the retrieved chunks (with an explicit "I don't know" fallback instead of hallucinating).
- **Vector search** — retrieval is powered by MongoDB Atlas Vector Search (`$vectorSearch`), not naive in-memory cosine similarity.
- **Dual embedding backends** — a local, offline model (`Xenova/all-MiniLM-L6-v2` via `@huggingface/transformers`) and a hosted API model (Gemini embeddings), each with its own MongoDB collection and vector index. The app currently runs on the Gemini path end-to-end.
- **Single-page frontend** — no build step; a static `public/index.html` covers login, PDF upload, and the Q&A chat.
- **Containerized** — a multi-stage `Dockerfile` and `docker-compose.yaml` for reproducible runs.

## Architecture

```
┌──────────────┐     upload PDF      ┌──────────────────┐
│   Browser    │ ──────────────────► │  POST /api/v1/   │
│ (index.html) │                     │  ingest/upload   │
└──────────────┘                     └─────────┬────────┘
       │                                        │
       │ ask question                           ▼
       │                              extract text (unpdf)
       ▼                                        │
┌──────────────────┐                            ▼
│ POST /api/v1/    │                    split into overlapping
│ question/answer  │                    chunks (1000 chars, 200
└─────────┬────────┘                    overlap)
          │                                      │
          ▼                                      ▼
  embed question                       embed each chunk
  (Gemini embeddings)                   (Gemini embeddings)
          │                                      │
          ▼                                      ▼
  $vectorSearch on MongoDB  ◄──────────  insertMany into MongoDB
  Atlas (top-k chunks)                   (pdfchunkgems collection)
          │
          ▼
  build prompt with retrieved
  context + ask Gemini (LLM)
          │
          ▼
  answer + cited sources
  returned to the browser
```

## Tech Stack

| Layer                   | Choice                                                                                                                       |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Runtime                 | Node.js 24 (ESM, `"type": "module"`)                                                                                         |
| Web framework           | Express 5                                                                                                                    |
| Database                | MongoDB Atlas (via Mongoose)                                                                                                 |
| Vector search           | MongoDB Atlas Vector Search                                                                                                  |
| PDF parsing             | [`unpdf`](https://www.npmjs.com/package/unpdf)                                                                               |
| File uploads            | [`multer`](https://www.npmjs.com/package/multer) (in-memory storage)                                                         |
| Local embeddings        | [`@huggingface/transformers`](https://www.npmjs.com/package/@huggingface/transformers) — `Xenova/all-MiniLM-L6-v2` (384-dim) |
| Hosted embeddings + LLM | [`@google/genai`](https://www.npmjs.com/package/@google/genai) — Gemini                                                      |
| Frontend                | Static HTML/CSS/vanilla JS, no build step                                                                                    |
| Containerization        | Docker (multi-stage), Docker Compose                                                                                         |

## API Reference

All routes are mounted under `/api/v1`.

### Ingest

| Method | Path                    | Body                                             | Description                                                                                                          |
| ------ | ----------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/v1/ingest/test`   | —                                                | Health check                                                                                                         |
| `POST` | `/api/v1/ingest/upload` | `multipart/form-data`, field `file` (PDF, ≤10MB) | Extracts text, chunks it, embeds each chunk, and stores it. Returns `{ message, pdfId, documentName, totalChunks }`. |

### Question

| Method | Path                      | Body                     | Description                                                                                                                                                          |
| ------ | ------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/v1/question/test`   | —                        | Health check                                                                                                                                                         |
| `POST` | `/api/v1/question/answer` | `{ "question": string }` | Retrieves the top matching chunks via vector search and returns `{ answer, sources }`, where each source includes `documentName`, `chunkIndex`, `score`, and `text`. |

### PDF

| Method | Path                            | Description                                                                               |
| ------ | ------------------------------- | ----------------------------------------------------------------------------------------- |
| `GET`  | `/api/v1/pdf/test`              | Health check                                                                              |
| `GET`  | `/api/v1/pdf/getUniqueDocNames` | Returns `{ documentNames: string[] }` — the distinct set of documents currently ingested. |
